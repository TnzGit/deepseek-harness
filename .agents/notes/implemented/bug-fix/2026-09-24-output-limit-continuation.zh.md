# Agent Note: 继续有用的输出触顶响应

Status: implemented

[English](2026-09-24-output-limit-continuation.md) | 中文

## Problem

模型可能只生成了推理内容就耗尽单次请求的输出预算。用户任务尚未完成，但以 `max-tokens` 结束整个轮次会迫使用户手动发送“继续”。提高单次请求上限只能推迟相同问题，还会为输出预留更多上下文窗口。

## Decision

agent loop 会提交每段输出触顶的 assistant 消息及其提供方回放元数据。如果该段包含文本或推理，且内容不同于上一段触顶输出，循环会写入一条简短、持久的插件来源续跑消息，并在同一轮次开启下一步骤。请求准备保留当前推理等级，正常的步骤间压缩策略照常生效。后续响应完成时，轮次以 `completed` 结束。

`agent-loop` 设置分节提供 `maxOutputContinuations`（默认 16，零表示关闭恢复）和 `maxContinuedOutputTokens`（默认 524288）。这些限制按轮次生效，无需重启服务即可调整。输出为空或机械重复、达到续跑次数或累计输出预算时，恢复以 `max-tokens` 停止。循环不会执行截断响应中未完成的工具调用。

## Alternatives considered

**只提高 `maxTokens`。** 更大的单次请求仍有有限上限，占用更多预留上下文，也无法保证跨请求自主推进。

**每次输出触顶都无条件重试。** 空响应和重复推理可能无限消耗本地算力。显式的单轮限制和保守的重复检测保留停止条件。

**不记录提示而静默重试。** 下一次请求将无法从持久会话日志重建。插件来源的 `user/message` 让模型可见输入与回放历史保持一致。

## Consequences

有用的部分推理可以跨过单次提供方请求上限继续生成，且不改变模型的 thinking 等级。每次续跑都会重新发送保留的历史，因此消耗上下文并可能触发压缩；这并非无限输出预算。如果提供方不报告 token 用量，则在可得时按请求输出上限计入安全限制，而续跑次数限制始终有效。简短的内部提示会作为注入上下文出现在会话历史里。

## Testing

agent-loop 测试覆盖纯推理触顶后完成、保留 `xhigh` 等级和 checkpoint 历史、重复内容止损、配置的续跑次数，以及关闭续跑时原有的触顶停止行为。设置测试覆盖实时更新和非法限制。
