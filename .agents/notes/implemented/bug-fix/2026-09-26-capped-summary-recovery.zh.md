# Agent Note: 摘要触顶后的压缩恢复

Status: implemented

[English](2026-09-26-capped-summary-recovery.md) | 中文

## 问题

长会话即使达到自动压缩阈值，摘要器仍可能反复耗尽输出上限，导致 checkpoint 一直无法写入。随后沿用未缩减的历史请求模型，最终触及提供方的上下文限制。若适配器隐藏实际默认输出上限，请求接纳也无法预留提供方实际使用的输出预算。

## 决策

基础压缩后端在摘要因 `MAX_TOKENS` 失败后，按 token meter 的计量结果逐次缩小待摘要前缀。每个前缀都在完整的工具调用与结果之后结束，额外尝试次数由 `summaryRangeRetries` 限制。每次失败只关闭持久标记，不写入半截 checkpoint。范围不可分割或重试耗尽时保留原始摘要错误。

pi-ai 适配器向 LLM 服务报告模型解析后实际采用的 `maxTokens`，包括目录值和路由回退值。对于 `purpose: 'compaction'` 的请求，只要模型声明支持 `off`，就选用它，不受普通轮次的默认推理等级影响。没有 `off` 的模型保留提供方行为。

## 考虑过的替代方案

- **只提高摘要输出上限**——不予采纳，因为较长历史仍可能耗尽更大的上限，尤其是提供方把 token 花在推理上时。
- **写入被截断的摘要**——不予采纳，因为不完整的 checkpoint 可能悄悄遗漏必须保留的工作。
- **降低普通轮次的推理等级**——不予采纳，因为压缩是独立的辅助请求，不应改变用户选择的 thinking 等级。

## 后果

摘要触顶时可以在不修改 vLLM 服务或丢弃部分历史的情况下收敛。恢复会增加模型调用，但受到 `summaryRangeRetries` 限制；没有安全的配对切分点时仍保持失败关闭。暴露实际输出上限后，原先被隐藏目录默认值的路由可能更早触发压力处理。
