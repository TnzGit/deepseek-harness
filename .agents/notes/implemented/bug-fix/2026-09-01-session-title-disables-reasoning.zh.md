# Agent Note：会话标题请求关闭受支持的推理

状态：已实现

[English](2026-09-01-session-title-disables-reasoning.md) | 中文

## 问题

内置会话标题提供方为辅助模型调用设置了较小的输出预算。如果推理模型的部署默认值是高强度思考，它可能把预算全部用于私有推理而不返回标题，导致自动命名虽已成功发起，界面仍保留回退标题。

## 决策

pi-ai 适配器对 `session-title` 与 `compaction` 采用相同规则：所选模型明确支持 `off` 时，辅助请求使用该档位，不继承请求或 profile 的默认推理档位。没有公开 `off` 的模型保留提供方默认值，因为适配器不能声称路由支持并未声明的控制。主 Agent 请求继续使用其选定的思考档位。

## 备选方案

- **提高标题输出上限。** 否决，因为它只会延后同一种失败，并把更多输出 token 用在与标题无关的推理上。
- **在模型服务器关闭思考。** 否决，因为服务器默认值也服务于有意使用推理的主 Agent 请求。
- **只在内置标题提供方设置 `reasoningEffort: 'off'`。** 否决，因为按用途选择推理档位的逻辑已经属于适配器，适配器能在网络 I/O 前检查实际选中的模型。

## 测试

适配器测试覆盖 DeepSeek 风格与 Qwen chat-template 请求，验证 `compaction` 和 `session-title` 都会关闭受支持的推理，同时保留普通请求配置的档位。

## 后果

在可控制推理的模型上，标题生成会把有限输出预算用于可见标题文本。未在能力声明中包含 `off` 的路由仍可能把预算消耗在提供方默认推理上；部署必须先描述该能力，适配器才能关闭它。
