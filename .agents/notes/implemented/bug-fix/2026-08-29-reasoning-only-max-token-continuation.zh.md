# Agent Note: 从可重放检查点续跑达到输出上限的纯推理响应

Status: implemented

[English](2026-08-29-reasoning-only-max-token-continuation.md) | 中文

## Problem

长思考模型可能把单次请求的全部输出预算消耗在私有推理中，以 `max-tokens` 结束，却没有可见回答或工具调用。此时推理仍在推进、任务也尚未完成，但轮次看起来已经停住。统一提高所有模型的输出上限只能推迟相同的终止条件，还会减少长会话可用的输入余量。

## Decision

agent loop 只识别一种狭窄且可恢复的情况：成功的 `max-tokens` 结束，包含非空推理，没有非空可见文本，也没有工具调用。循环会提交该 assistant 消息，追加持久化的 `agent/max-token-continuation` 事件，并在同一轮次中打开新步骤。请求重建会先把这条达到上限的推理消息替换成内部 assistant 文本检查点，再追加恢复用的用户提示。这种与提供方无关的投影能防止丢弃历史私有推理的聊天模板重新开始分析，同时让持久化消息和用户可见消息继续保持私有。如果压力压缩已经遮蔽源消息，请求重建会沿用压缩后的检查点，不会恢复完整推理。

`maxTokenContinuations` 按轮次限制该行为，默认四次，位于实时 `agent-loop` Settings 段中，也接受零来禁用恢复。`maxTokenContinuationOutputTokens` 独立限制该链中达到上限的响应累计输出量，默认 163,840 token。两个值都在轮次边界捕获。续跑与前一个检查点完全重复时也会停止。次数、token 或进度上限任一耗尽后，轮次都会以 `{ kind: 'max-tokens', autoContinuation: 'exhausted' }` 结束；客户端随后会说明自动续跑已经执行过。

续跑是普通的下一步骤请求。它不会覆盖提供方、模型、输出上限、thinking 或 reasoning effort。尤其是，恢复会保留原路由的 thinking 设置，而不是降低或关闭它。包含可见部分文本或工具调用的响应仍会在达到上限时结束，因为重放它们可能导致可见输出或副作用重复。

## Alternatives considered

**把模型 `maxTokens` 提高到 65,536。** 不作为永久机制。它可以是部署选择，但模型仍可能耗尽更大的上限，而且预留该预算会减少上下文压力判断所使用的输入预算。

**恢复时关闭或降低 thinking。** 不采用，因为这会在任务最困难的节点悄然改变用户选择的模型行为。续跑会保留实际生效的请求设置。

**不设置次数、token 和进度上限。** 不采用，因为反复出现的纯推理结束可能无限消耗时间和算力。

**只传递恢复指令。** 不采用，因为 Qwen 类聊天模板可能丢弃历史推理块，使模型只收到续跑要求，却看不到此前的工作状态。

**自动续跑可见部分回答或工具调用。** 不采用，因为下次请求可能重复文本或再次发出操作。这些情况保留现有的显式“继续”流程。

## Verification

agent-loop 测试覆盖检查点替换、压缩遮蔽后的回退、各次请求的 reasoning effort 一致、次数与累计 token 耗尽、完全重复时停止、通过 Settings 禁用，以及存在可见输出时不触发。真实 Cordis Loader 快照通过 DeepSeek 直连 SSE 适配器制造纯推理 length 结束，并在请求线上确认恢复请求看得到检查点，同时两次调用都保留 `thinking: { type: 'enabled' }`、`reasoning_effort: 'max'` 和相同输出上限。客户端投影与渲染测试覆盖普通提示和自动续跑耗尽提示。

## Consequences

纯推理输出上限结束无需用户输入即可恢复，并能跨越提供方模板保留模型的实际工作状态。每次续跑都可能再消耗一份完整输出预算，但独立的次数、累计 token 与完全重复保护可阻止无限工作。持久事件重建让回放、持久化恢复、请求不变量和压缩对隐藏检查点与恢复提示保持一致。运维人员可以设置 `maxTokenContinuations: 0` 禁用恢复，也可以调整任一上限并接受相应算力成本。
